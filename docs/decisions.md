# Decisions

Architecture context: [architecture.md](architecture.md). Phases: [phase.md](phase.md).

| Decision                            | Choice                                                                                                                                                                 | Why                                                                                                      | Revisit if                                                                                                 | Status                            |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------- |
| Monorepo                            | Turborepo + pnpm, with a uv workspace; each Python package has a `package.json` wrapping uv commands                                                                   | one task graph and cache across TS and Python                                                            | Turbo cannot express a needed Python task dependency                                                       | Decided                           |
| Source of types                     | Pydantic v2 in `packages/core`; generated JSON Schema -> TS types + Zod; no hand-written duplicates                                                                    | one definition; drift fails CI (`pnpm schema:check`)                                                     | a construct cannot be generated cleanly (fix the model first)                                              | Decided                           |
| Core purity                         | `notary_core` is pure Python: no I/O, clock, randomness, LLM                                                                                                           | monitor stays small and auditable; deterministic by construction                                         | never relax; add adapters outside core                                                                     | Decided                           |
| Language for eval and fuzz          | Python                                                                                                                                                                 | AgentDojo and Hypothesis are Python                                                                      | AgentDojo is unavailable                                                                                   | Decided                           |
| Web                                 | Next.js (App Router) + React Flow                                                                                                                                      | provenance graph needs a node-graph library                                                              | React Flow cannot render the required graph                                                                | Decided                           |
| LLM access                          | raw Anthropic SDK with a small hand-written tool loop; no agent framework                                                                                              | control flow is ours; record/replay is trivial                                                           | the loop outgrows a few hundred lines                                                                      | Decided                           |
| Model independence demo             | a second non-Claude model (e.g. local Qwen via Ollama), only to demonstrate I6                                                                                         | shows the guarantee does not depend on the model                                                         | Hijacked Mode alone is judged sufficient                                                                   | Decided                           |
| Policy language                     | hand-written Python rules, not OPA/Cedar                                                                                                                               | six fixed steps; no policy-language surface to audit                                                     | policies must be user-authored                                                                             | Decided                           |
| Storage                             | SQLite for ledger, audit and world                                                                                                                                     | single file, deterministic reset, no server                                                              | concurrent multi-user deployment                                                                           | Decided                           |
| Server                              | FastAPI + WebSocket event stream                                                                                                                                       | Pydantic-native; OpenAPI for REST types                                                                  | event rate exceeds one process                                                                             | Decided                           |
| Delivery                            | Docker Compose + public deploy + offline fallback                                                                                                                      | venue connectivity is a risk                                                                             | n/a                                                                                                        | Decided                           |
| Discriminated unions in JSON Schema | emitted as `anyOf` + `discriminator` (custom `GenerateJsonSchema` in `packages/core/scripts/export_schema.py`)                                                         | Pydantic's `oneOf` generates poor Zod                                                                    | json-schema-to-zod handles `oneOf` well                                                                    | Decided                           |
| TypeScript version                  | pinned to 6.0.3                                                                                                                                                        | `typescript-eslint` supports `<6.1` only                                                                 | `typescript-eslint` supports TS 7                                                                          | Decided                           |
| uv in package scripts               | `uv run --no-sync`                                                                                                                                                     | parallel `uv run` calls corrupted the shared env; run `uv sync` first                                    | uv serializes syncs                                                                                        | Decided                           |
| Gateway placement                   | Proposed: pure labeling/splitting logic in `packages/core`; tool-call I/O adapter and MCP proxy in `packages/mcp-proxy`, owned entirely by lane A (lane C consumes it) | core must stay pure (no I/O), yet I1 complete mediation must be testable                                 | the team prefers a single gateway package                                                                  | Proposed, needs team confirmation |
| Classifier-only baseline            | Stand-in heuristic injection filter (regex/keyword rules), labeled "stand-in" in the UI                                                                                | no model dependency, deterministic, and enough to show that data-only poisoning (A3) passes a classifier | a real classifier (e.g. a hosted prompt-injection model) is available; swap it in behind `ResultPreFilter` | Proposed, needs team confirmation |
| Policy floor merge (equal rank)     | Compiler marker can only tighten the table floor. At equal rank: `named_source` -> compiler's, `ledger` -> floor's, `endorse`/`free` -> proposed. A ledger floor must name its ledger; `DEFAULT_POLICY` is read-only | the user-named source is unknown to the table, while the reviewed table decides which ledger authorizes a parameter (I2) | a ledger needs to be chosen per request rather than per table                                              | Decided (#52)                     |
| Readers encoding | `"*"` in `readers` = public (anyone may read); `()` = nobody. Join is intersection with `"*"` as identity. Every join output goes through `normalize_readers` (sorted, unique, any `"*"` collapses to `("*",)`). The Value Store (P3a) and the oracle (P2) use the same encoding and `normalize_readers` | intersection is then a clean lattice join, and equal reader sets serialize identically (I3) | the Value Store needs per-principal grants beyond a flat set | Decided (#40) |
| Integrity order | `untrusted` < `endorsed` < `trusted`; derived values take the lowest, so derived(trusted, endorsed) = endorsed. `endorsed` by label alone never admits a guarded parameter: step 4 matches the exact canonical value against the ledger/endorsement record | a derived value inherits `endorsed` without the user having endorsed that exact value (I2, A6) | derived values carry their own endorsement record | Decided (#40) |
| Audit anchoring | The chain alone cannot detect tail truncation. The server persists the head hash and length outside the log, the X-ray shows the verified head, and `notary replay` accepts `--expect-head` / `--expect-length` (passed to `verify_chain_detailed`) | a valid-looking truncated log would otherwise hide the last entries (tamper evidence is only as strong as the external anchor). Reference implementations: `notary replay` (P2) and `notary_server.anchors` (`AnchorStore` on SQLite, `anchored_append`, `GET /runs/{run_id}/anchor`; #139) | the audit log is stored somewhere that already guarantees completeness | Proposed, needs team confirmation |
| Write-ahead audit | The decision entry is appended before any effect runs, and an append failure is treated as BLOCK. Owner: the gateway adapter (P3a) and the runner (P3b) | no effect may happen without a durable record of the decision that allowed it (protects I1). Reference implementation: `notary_world.executor` appends `decision_made` before the world tool runs (P2) | audit appends become asynchronous or best-effort | Proposed, needs team confirmation |
| Sensitive-parameter table data | `DEFAULT_POLICY` (hand-authored, reviewed with `scripts/print_sensitive_params.py`): destinations get a `ledger` floor (`contacts`, `channels`), the payment `payee` gets an `endorse` floor so a contract can make a novel payee ESCALATE with a diff card (an exact ledger match is still ALLOW and a near match still BLOCK; #119), mutating identifiers (`delete_email`, `add_contact`) get `endorse`, payload text, `amount` and read-only ids get `free`. `assert_covered` fails when a non-read tool has a param without a binding (unknown tools count as irreversible). `send_email.bcc` is not listed until the world defines it; the coverage helper will force the decision | the table is the trusted base for I2/I3; a new param must never silently fall back to a looser rule. `amount` is `free` because the effect budget bounds damage; choosing among trusted amounts is the documented "steer among trusted values" limitation | stricter `amount` floor if the budget proves too weak | Proposed (#53, payee floor #119) |
| Oracle location | The oracle (goal predicates, invariant checks I1-I6) and the fuzz harness live in `packages/world`; `core` holds only the `OracleResult` / `InvariantResult` models | `core` stays pure; the oracle diffs world state independent of agent claims | the oracle needs state `core` cannot see | Decided (P2) |
| Argument labeling stand-in | `notary_world.executor.DefaultArgResolver` labels raw tool-call arguments (same value / span of a stored value / model-authored text with quoted-secret readers) until the P3a Gateway exists | the executor needs labeled arguments now; the resolver has the same call signature as the real one | the P3a Gateway lands (replace behind `ArgResolver`) | Proposed (P2) |
| Execution form of guarded values | The executor hands world tools the canonical form of `iban`, `email`, `url_host` and `amount` arguments (`judged_tool_args`); identifiers and free text keep their typed text | what the monitor judges (the canonical value) must be what runs (#111, #112) | the P3a Gateway owns this mapping | Decided (P2) |
| Fixture world setup | Poison per attack lives in the Python table `ATTACK_SETUPS`; the JSON fixtures keep case, scripted calls, goals and expected outcomes | the frozen `AttackFixture` cannot express calendar, Slack or tool-description poison | the fixture format gets a poison field (contract change) | Proposed (P2) |
| Payee marker | `pay_bill` / `send_money` `payee` has an `endorse` floor; plain bill contracts mark it `endorse` (novel payee ESCALATEs with a diff card, near match BLOCKs, exact ledger match ALLOWs); the A9 contract keeps `ledger` | threat-model A3, stage-script step 3 (#119) | stricter payee policy | Decided (#119) |
| Contract monotonicity (I5) | `notary_core.contract.widening_reasons(old, new)` returns sorted reasons; empty = narrower or equal. Removing tools/params, lowering budgets and tightening markers are allowed; `contract_id`, `user_intent` and every pinned `manifest_hash` must stay equal. A tool's `effect` may only move toward `irreversible` (the class the monitor scrutinises most), so moving toward `read` is a widening. Literal values compare by type and value (`1` is not `True`) | free-text intent cannot be compared for "narrower"; a lower effect class would skip checks the user's contract relied on | the compiler can produce a revised contract mid-session with user re-approval | Decided (#55) |
| Run socket close codes and threading | Errors on `WS /ws/runs/{scenario}` are close codes in the private range (4400 bad request, 4404 unknown scenario, 4409 run conflict, 4422 unsupported command, 4501 mode unavailable) with a fixed reason; frames are only events. Sources are blocking iterators driven one step at a time in worker threads inside an anyio task group; a cancelled stream waits for the step in flight, then closes the iterator | `Event` and `Command` are frozen, so an error cannot be a frame; `iterate_in_threadpool` abandons a running step on cancel, and a running generator cannot be closed, so its `finally` blocks would not run | the web client needs error details beyond a code and a reason | Decided (#135) |
| Command bodies on REST routes | A route that takes a strict command model (`PoisonWorldCommand`) validates the decoded JSON body in JSON mode (a `BeforeValidator` re-encodes it), the same way the socket's `COMMAND_ADAPTER.validate_json` does. The OpenAPI body schema stays the plain command | FastAPI validates bodies in Python mode, where a strict tuple field such as `lanes` rejects a JSON array, so the golden sample command would be refused | the command models stop being strict, or FastAPI validates bodies in JSON mode | Decided (#136) |

## Conventions

- IDs (A1-A14, I1-I6, component names, decision-order steps) are stable; never rename them. Tests, code and UI cite them.
- Generated files are never hand-edited ([list](../CLAUDE.md)).
- Docs are updated in the same commit as the behavior change.
