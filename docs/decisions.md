| Storage                             | SQLite for ledger, audit and world                                                                                                                                     | single file, deterministic reset, no server                                                              | concurrent multi-user deployment                                                                           | Decided                           |
| Server                              | FastAPI + WebSocket event stream                                                                                                                                       | Pydantic-native; OpenAPI for REST types                                                                  | event rate exceeds one process                                                                             | Decided                           |
| Delivery                            | Docker Compose + public deploy + offline fallback                                                                                                                      | venue connectivity is a risk                                                                             | n/a                                                                                                        | Decided                           |
| Discriminated unions in JSON Schema | emitted as `anyOf` + `discriminator` (custom `GenerateJsonSchema` in `packages/core/scripts/export_schema.py`)                                                         | Pydantic's `oneOf` generates poor Zod                                                                    | json-schema-to-zod handles `oneOf` well                                                                    | Decided                           |
| TypeScript version                  | pinned to 6.0.3                                                                                                                                                        | `typescript-eslint` supports `<6.1` only                                                                 | `typescript-eslint` supports TS 7                                                                          | Decided                           |
| uv in package scripts               | `uv run --no-sync`                                                                                                                                                     | parallel `uv run` calls corrupted the shared env; run `uv sync` first                                    | uv serializes syncs                                                                                        | Decided                           |
| Gateway placement                   | Proposed: pure labeling/splitting logic in `packages/core`; tool-call I/O adapter and MCP proxy in `packages/mcp-proxy`, owned entirely by lane A (lane C consumes it) | core must stay pure (no I/O), yet I1 complete mediation must be testable                                 | the team prefers a single gateway package                                                                  | Proposed, needs team confirmation |
| Classifier-only baseline            | Stand-in heuristic injection filter (regex/keyword rules), labeled "stand-in" in the UI                                                                                | no model dependency, deterministic, and enough to show that data-only poisoning (A3) passes a classifier | a real classifier (e.g. a hosted prompt-injection model) is available; swap it in behind `ResultPreFilter` | Proposed, needs team confirmation |
| Policy floor merge (equal rank)     | Compiler marker can only tighten the table floor. At equal rank: `named_source` -> compiler's, `ledger` -> floor's, `endorse`/`free` -> proposed. A ledger floor must name its ledger; `DEFAULT_POLICY` is read-only | the user-named source is unknown to the table, while the reviewed table decides which ledger authorizes a parameter (I2) | a ledger needs to be chosen per request rather than per table                                              | Decided (#52)                     |
| Readers encoding | `"*"` in `readers` = public (anyone may read); `()` = nobody. Join is intersection with `"*"` as identity. Every join output goes through `normalize_readers` (sorted, unique, any `"*"` collapses to `("*",)`). The Value Store (P3a) and the oracle (P2) use the same encoding and `normalize_readers` | intersection is then a clean lattice join, and equal reader sets serialize identically (I3) | the Value Store needs per-principal grants beyond a flat set | Decided (#40) |
| Integrity order | `untrusted` < `endorsed` < `trusted`; derived values take the lowest, so derived(trusted, endorsed) = endorsed. `endorsed` by label alone never admits a guarded parameter: step 4 matches the exact canonical value against the ledger/endorsement record | a derived value inherits `endorsed` without the user having endorsed that exact value (I2, A6) | derived values carry their own endorsement record | Decided (#40) |
| Audit anchoring | The chain alone cannot detect tail truncation. The server persists the head hash and length outside the log, the X-ray shows the verified head, and `notary replay` accepts `--expect-head` / `--expect-length` (passed to `verify_chain_detailed`) | a valid-looking truncated log would otherwise hide the last entries (tamper evidence is only as strong as the external anchor). Reference implementations: `notary replay` (P2) and `notary_server.anchors` (`AnchorStore` on SQLite, `anchored_append`, `GET /runs/{run_id}/anchor`; #139); CP2 wires every cassette and live run through `anchored_append` | the audit log is stored somewhere that already guarantees completeness | Proposed, needs team confirmation |
| Write-ahead audit | The decision entry is appended before any effect runs, and an append failure is treated as BLOCK. Owner: the gateway adapter (P3a) and the runner (P3b) | no effect may happen without a durable record of the decision that allowed it (protects I1). Reference implementation: `notary_world.executor` appends `decision_made` before the world tool runs (P2) | audit appends become asynchronous or best-effort | Proposed, needs team confirmation |
| Sensitive-parameter table data | `DEFAULT_POLICY` (hand-authored, reviewed with `scripts/print_sensitive_params.py`): destinations get a `ledger` floor (`contacts`, `channels`), the payment `payee` gets an `endorse` floor so a contract can make a novel payee ESCALATE with a diff card (an exact ledger match is still ALLOW and a near match still BLOCK; #119), mutating identifiers (`delete_email`, `add_contact`) get `endorse`, payload text, `amount` and read-only ids get `free`. `assert_covered` fails when a non-read tool has a param without a binding (unknown tools count as irreversible). `send_email.bcc` is not listed until the world defines it; the coverage helper will force the decision | the table is the trusted base for I2/I3; a new param must never silently fall back to a looser rule. `amount` is `free` because the effect budget bounds damage; choosing among trusted amounts is the documented "steer among trusted values" limitation | stricter `amount` floor if the budget proves too weak | Proposed (#53, payee floor #119) |
| Oracle location | The oracle (goal predicates, invariant checks I1-I6) and the fuzz harness live in `packages/world`; `core` holds only the `OracleResult` / `InvariantResult` models | `core` stays pure; the oracle diffs world state independent of agent claims | the oracle needs state `core` cannot see | Decided (P2) |
| Argument labeling stand-in | `notary_world.executor.DefaultArgResolver` labels raw tool-call arguments (same value / span of a stored value / model-authored text with quoted-secret readers). Replaced as the default by core's `ArgumentResolver`; `start_run` now defaults to `make_labeler(world_labeling_policy())` and `ArgumentResolver()`. `DefaultArgResolver` and `FakeGateway` stay for tests, and `test_gateway_equivalence.py` keeps them honest | the executor needed labeled arguments before the P3a Gateway existed; the real pieces have the same call signatures | never; the stand-ins can be deleted once no test needs them | Decided (#142) |
| Execution form of guarded values | The executor hands world tools the canonical form of `iban`, `email`, `url_host` and `amount` arguments (`judged_tool_args`); identifiers and free text keep their typed text | what the monitor judges (the canonical value) must be what runs (#111, #112) | the P3a Gateway owns this mapping | Decided (P2) |
| Fixture world setup | Poison per attack lives in the Python table `ATTACK_SETUPS`; the JSON fixtures keep case, scripted calls, goals and expected outcomes | the frozen `AttackFixture` cannot express calendar, Slack or tool-description poison | the fixture format gets a poison field (contract change) | Proposed (P2) |
| Payee marker | `pay_bill` / `send_money` `payee` has an `endorse` floor; plain bill contracts mark it `endorse` (novel payee ESCALATEs with a diff card, near match BLOCKs, exact ledger match ALLOWs); the A9 contract keeps `ledger` | threat-model A3, stage-script step 3 (#119) | stricter payee policy | Decided (#119) |
| Contract monotonicity (I5) | `notary_core.contract.widening_reasons(old, new)` returns sorted reasons; empty = narrower or equal. Removing tools/params, lowering budgets and tightening markers are allowed; `contract_id`, `user_intent` and every pinned `manifest_hash` must stay equal. A tool's `effect` may only move toward `irreversible` (the class the monitor scrutinises most), so moving toward `read` is a widening. Literal values compare by type and value (`1` is not `True`) | free-text intent cannot be compared for "narrower"; a lower effect class would skip checks the user's contract relied on | the compiler can produce a revised contract mid-session with user re-approval | Decided (#55) |
| Run socket close codes and threading | Errors on `WS /ws/runs/{scenario}` are close codes in the private range (4400 bad request, 4404 unknown scenario, 4409 run conflict, 4422 unsupported command, 4501 mode unavailable) with a fixed reason; frames are only events. Sources are blocking iterators driven one step at a time in worker threads inside an anyio task group; a cancelled stream waits for the step in flight, then closes the iterator | `Event` and `Command` are frozen, so an error cannot be a frame; `iterate_in_threadpool` abandons a running step on cancel, and a running generator cannot be closed, so its `finally` blocks would not run | the web client needs error details beyond a code and a reason | Decided (#135) |
| Command bodies on REST routes | A route that takes a strict command model (`PoisonWorldCommand`, `ArenaStartCommand`) validates the decoded JSON body in JSON mode (a `BeforeValidator` re-encodes it), the same way the socket's `COMMAND_ADAPTER.validate_json` does. The OpenAPI body schema stays the plain command | FastAPI validates bodies in Python mode, where a strict tuple field such as `lanes` rejects a JSON array, so the golden sample command would be refused | the command models stop being strict, or FastAPI validates bodies in JSON mode | Decided (#136) |
| Manifest hash recipe | ONE recipe: `notary_core.pinning.manifest_hash(ToolManifest(name, description, input_schema))`. The world builds each manifest (`notary_world.tools.tool_manifest`, schema text from `schema_text`, shared with the agent's tool schemas) and `default_manifest_hash` / `tool_manifest_hash` delegate to it. The effect class is no longer part of the hash | the compiler, the adapter and the engine must agree on the pinned value, or step 1 blocks every call of a compiled contract (A10) | the manifest needs a field the schema text cannot carry | Decided (#142) |
| Engine versus adapter on the demo path | The server's runner drives the lane-B `RunEngine` with the real core labeler, resolver and monitor. `notary_mcp_proxy.Gateway` is the I/O adapter for a real MCP server (P6). `test_adapter_agrees_with_the_engine` proves both give the same verdicts, reason codes, world diff and session on both bills | one mediation path on the stage, and a test that the other cannot drift | the team wants the adapter on the demo path (the runner, endorsement flow and oracle wiring change; the CP2 test stays) | Decided (#142), team may revisit |
| LLM provider | Groq (`groq` SDK, `GroqClient`, `GROQ_API_KEY`); the Anthropic client, its tests and the `anthropic` dependency are removed. `DEFAULT_MODEL` is `openai/gpt-oss-120b`; `NOTARY_LIVE_MODEL` changes the model `mode=live` asks | the project has a Groq key and no Anthropic key, so the live path could never run; the model name is part of every prompt and so of every cassette key, so a prompt names the model that answers it | an Anthropic key and a reason to keep both providers | Decided (#182) |
| Hijack susceptibility is model-dependent; the NOTARY guarantee is not | A live run's chance of following the swapped IBAN depends on the model (2026-10-17 probe in [demo.md](demo.md#live-models-what-a-real-model-does-with-the-swapped-iban): `gpt-oss-20b` 1/10 Undefended and 2/10 Classifier, `gpt-oss-120b` 0/10, `qwen3.8-27b` 0/10), and the scenario text and the scenario fixtures are NOT changed to make a model fall for it. The NOTARY lane reached the attacker goal 0 times for every model that ran it. Claims about attack success per model and lane are measured, dated and live in the eval ([#240](https://github.com/Chirag8405/Notary/issues/240)), not in the stage script | the monitor assumes a fully hijacked agent (I6); making the demo depend on a model's gullibility would make the demo, not the system, model-dependent | a model that is hijacked reliably enough to demonstrate on stage, or the P6 model-dependence eval | Decided (#182) |
| Optional payload parameters in the run contract | The run's contract is the scenario's contract plus every optional parameter of its tools at the sensitive-parameter table's floor (`with_optional_params`); for `pay_bill.reference` that floor is `free`, and it is not lowered. Because the budget step counts every payload byte as egress, a contract that admits a payload parameter gets at least 100 bytes of `max_egress_bytes`. Confidentiality still blocks a reference that carries data the payee may not read | real models always fill `reference`; with the old contract the legitimate bill was blocked at scope (and at budget with 0 egress) | the table gets a stricter floor for `reference`, or egress needs a different unit | Decided (#182) |
| Scripted cassettes | The committed cassettes are recorded by `notary_server.recording` in scripted mode (`"model": "scripted-v1"`): real prompt-hash keys, fixed responses, no network or key. `scripts/record_cassettes.py --live` records from the Groq API (`GROQ_API_KEY`, model `DEFAULT_MODEL` = `openai/gpt-oss-120b`). `test_committed_scripted_cassettes_are_current` fails when a prompt changed, and skips once cassettes are live | the stage replay and the CP2 proof must work without a key; a first real recording exists but does not reproduce the scripted behaviour (findings in #182) | the real findings in #182 are resolved and the real cassettes are committed: delete this row | Decided (#142), temporary |
| Anchor restart | `AnchorStore.restart` lets the FIRST entry of a chain replace the anchor of a reused run id; `record` still never lets an anchor shrink. `anchored_append` calls `restart` for a one-entry chain | golden run ids repeat (`run-<scenario>-<lane>`), so a replayed run must not fail with `anchor cannot move backwards` | run ids become unique per run | Decided (#142) |
| Hash link in the decision stream | The "hash link" is the short content hash of an argument (the first 8 hex characters of `ValueRef.content_hash`); the tool's manifest hash is shown in the row header. Clicking it selects the value in the graph and the inspector | events carry no audit-chain hash; the verified head is the anchor footer (`GET /runs/{run_id}/anchor`) | events carry the hash of their audit entry | Decided (#165, #173) |
| Stage step 3 is the Reject beat | In stage-script step 3 the presenter presses Reject: the attacker goal stays not reached (green) and the run ends blocked. Confirm pays the swapped IBAN (the approved value is written to the ledger and the second decision is ALLOW) and is shown only as an optional residual-risk beat (A3: user approves a bad payee despite the diff). A third choice, "Use nearest known value", proposes the call again with the ledger's value (see the next row) | the card holds the attacker IBAN, so the correct payee cannot be confirmed on it; Confirm pays the attacker by design of the approval | an action that re-proposes the nearest known payee exists | Decided (#198) |
| Use the nearest known value | The `endorsement_decision` command has a third value, `use_nearest`: the engine rejects the proposed value (no ledger write, no approval used) and proposes a new call `<call_id>.nearest` with the nearest ledger value of every card row, judged by the monitor like any other proposal. A card whose rows lack such a value is blocked. The card shows the button only when every row has one. The scripted `poisoned_bill.notary` cassette records this run too | the swapped IBAN can never be written to the ledger by this path (I4), and the replacement is not trusted by decree: it is ALLOWed only through an exact ledger match (I2) | a separate command; a ledger write of the nearest value | Decided (#207) |
| Classifier-flagged spans | Deferred: the graph has no red "flagged" outline. The model has a `flagged` bit, but nothing supplies it | no event or route reports which spans the stand-in classifier flagged | an event or route reports flagged spans | Decided (#173), deferred |
| World diff at CP3 | The bottom band shows an effects list ("What changed": the executed effects in order, or "nothing executed") instead of a before/after world diff | the stream carries executed effects only, no world snapshot | a world-state event or route exists | Decided (#173), temporary |
| Endorsement resolution | The UI reads how a card ended from the run's own events (`cardOutcomes` in `@notary/ui`), not from a list. The runner blocks on a card, so the first event after `endorsement_requested` (skipping `value_labeled`) is the outcome: `decision_made` for the call with ALLOW is an approval, BLOCK is approved-then-refused, `call_proposed` of `<call>.nearest` is "use the nearest known value", anything else means not approved. The user's click, the only thing the stream cannot know, tells a rejection from a timeout ("no longer open"). "Approvals left" is the contract's `max_approvals` minus the cards approved before. A closed socket resolves nothing; 4409 turns an open card into "no longer open"; the `golden` replay does not answer cards. `GET /runs/{run_id}/endorsements` is removed | The stream already says it, in order, for free; a list needed a request per event and click, and (#235) a per-tab token to keep two tabs apart. The order is pinned by `test_what_follows_a_card` | a reject must be told from a timeout without the click (needs an event, a contract change) | Decided (#170, #172, #239) |
| Endorsement list read token | Superseded by #239. Each tab made a random token sent as `?token=` on its sockets and as `X-Notary-Token` on `GET /runs/{run_id}/endorsements`; the server kept `HMAC-SHA256(server_key, run_id NUL token)` and a socket without a good token closed `4400 invalid token` | It scoped the list to its owning tab without a contract change. With the list gone (resolution comes from the stream) nothing reads a token, so the route, the token, the HMAC and the 4400 check were removed in one change; the log filter stays, for session ids and as a safety net for a stray `token=` | | Superseded (#235 -> #239) |
| Playground sessions and limits | Hijacked Mode sessions get unguessable ids (128 random bits), an idle TTL (30 min) and a maximum age (2 h), are removed lazily on the next lookup (no thread, injected clock), and are capped per client (4) as well as per process (64). Every client address has a sliding-window budget for Hijacked Mode starts (10 per minute), calls (60) and the other playground POSTs (10, shared); over it is `429 too many requests` with `Retry-After`. The session id in the request path is redacted from the app's logs. All of it is in process memory, so one worker | The review of #241 found sessions that never expire (64 starts lock the playground until a restart), no rate limit, and sequential guessable ids; the id is the only credential of a session | a deploy with several workers (the state would have to be shared); a real identity per judge; trusting `X-Forwarded-For` by default | Decided (#242) |
| Poison and arena replay recordings | The REST runner behind "Poison the world" and the attacker arena replays recorded cassettes; an input or a seed without a recording answers `501 cassette miss`, which the panels explain ("This input has no recorded run") instead of falling back to another mode | No API key is needed and the demo is deterministic; a silent fallback would show a result that was not recorded | real recordings exist (#182), then custom payloads and other seeds can run | Decided (#136, #138, #215, #220) |
| Hijacked tool table is a guarded copy | The tool form's table (`apps/web/lib/hijacked-tools.ts`) is a copy of the server's `TOOL_SPECS`; a test compares it with the recorded `tools.specs` fixture entry by entry and `pnpm playground:fixtures:check` re-records that fixture from the server | A `GET /playground/tools` endpoint would remove the copy but adds a route and a contract; the test turns drift into a failure | drift ever bites | Decided (#216) |
| Hijacked Mode auto-rejects escalations | The judge plays the attacker, so an ESCALATE is rejected by the server at once; the step still reports `escalated` and the `endorsement_requested` event, and the panel has no approve action | Nobody can answer a card in this mode, and an approve button would let the judge grant their own attack | a mode where the judge plays the user | Decided (#137, #217) |
| Replay is a controlled player | Every `RunResult` shows a `ReplayPlayer` whose position is the number of events folded by `viewAt`; it opens on the whole run and a new run opens on its end. There is no timer and no autoplay | The same pure fold drives the live view and the replay, so a position never shows a state the stream did not have | a recorded-run video is wanted | Decided (#213, #221) |
| Three-lane view and modes | The three-lane view uses cassette mode: golden serves each lane its own stream (#193) and `legitimate_bill` its NOTARY stream only (#196). The page moves a golden choice to cassette and says so, never defaults to or selects `live` (it needs an LLM API key and is not reproducible), and shows a lane whose stream belongs to another lane as an error | a column must never show another lane's stream | #193 and #196 are fixed | Decided (#172, #191) |

## Conventions

- IDs (A1-A14, I1-I6, component names, decision-order steps) are stable; never rename them. Tests, code and UI cite them.
- Generated files are never hand-edited ([list](../CLAUDE.md)).
- Docs are updated in the same commit as the behavior change.
